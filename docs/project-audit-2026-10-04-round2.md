# Repeated audit and fixes — 4 October 2026, round 2

Baseline: deployed main e1dd987. The owner requested another audit, fixes and a repeated audit cycle. Three agents reviewed frontend, backend boundaries and delivery operations in parallel; the main agent independently reviewed the changes and exercised actual QA browser flows. CodeGraph remains disabled by owner choice.

## Findings and fixes

| Priority | Finding | Result and verification |
|---|---|---|
| P1 | An operator's work-scoped PAT retained privileged visibility into blind review conclusions | Browser operator authority is separated from scoped agent credentials across REST, MCP, status filtering and finding adjudication. Both real and demo operator accounts are covered; legitimate browser authority remains. |
| P1 | Database lock/query waits and connection-pool saturation could occupy requests and delay expiry workers | Runtime PostgreSQL lock and statement time are bounded; retryable REST failures return sanitized 503 with Retry-After. Schema migrations retain their own deliberate timeout policy. Contention checks use actual PostgreSQL and verify rollback followed by a successful retry. |
| P1 | CI reconciliation trusted the stored PR head/state when a synchronize/closed webhook was missing | Reconciliation observes the current GitHub PR before applying head, terminal state and credit. Webhook and queued reconciliation paths share one transition under task/submission locks; malformed observations fail closed and duplicate credit remains prohibited. This is recovery on a reconciliation trigger, not periodic polling of every PR. |
| P2 | Concurrent personal-token creation exceeded the quota; OAuth credentials also consumed PAT slots | Account locking serializes quota check and insertion. Eight simultaneous requests with nineteen personal tokens yield one success, seven conflicts and twenty active PATs. OAuth grant credentials have a separate lifetime and do not consume the personal-token quota. |
| P2 | An expired submission permit kept the registration form enabled, with no renewal action | Render and submit independently check the live clock; controlled PR fields survive renewal. Explicit server expiry also invalidates the permit when the client's clock is behind. Five state/clock regressions and real QA browser 409 → renew verified URL, SHA and summary retention. |
| P2 | Reloading the page lost the in-memory permit while the server remained FINALIZING | The same active owned lease can rotate the previous permit and recover the form. Actual PostgreSQL regressions reject old/foreign tokens and post-submission recovery. The second QA browser pass reloaded a FINALIZING task and successfully prepared a new permit, with no console errors. |
| P2 | Uncomputed readiness/impact appeared as measured 0/100 | Real project surfaces display that scoring is unavailable, alongside repository qualification. Demo numerical scores remain explicitly sample data; backend score/credit values are unchanged. |
| P2 | The public landing eagerly loaded the maintainer workspace | Workspace is a lazy chunk with localized loading/error recovery. Initial JavaScript decreased from 700418 to 684228 bytes, gzip 206482 to 204256; workspace chunk is 23438 bytes. The initial bundle still exceeds 500 kB. Direct owner URLs loaded in Russian, English and Chinese. |
| P1 | Deployment accepted a legacy worker heartbeat or mixed container releases | A read-only gate checks exact release image tags, unique healthy services and heartbeats after each worker's StartedAt, plus private/public readiness and public HTTPS/CSP/HSTS. Redirects and a 204 frontend cannot masquerade as success. current-sha advances only after these checks. |
| P1 | A rollback compatibility check before obtaining the deployment lock raced a new migration | The operator wrapper requests a schema guard that executes inside deploy.lock. A regression changes the schema when the lock is acquired and verifies refusal before mutations. Matching migration heads is necessary; operators still assess semantic compatibility. |
| P2 | Backup argument validation disappeared with python -O, and restore verification was ad hoc | Validation is unconditional; option-prefix/shell injection is rejected before file creation. A verifier checks encrypted/plain hashes, refuses production targets before reading the key, restores into a fresh local QA scratch database and removes only that database. |
| P2 | Shared-host release failures could leave temporary stage/archive files; redirects lacked HSTS | Cleanup is limited to that invocation's temporary paths. A 1 GiB free-disk preflight precedes release work; HTTPS www redirects carry HSTS. No global Docker prune or unrelated-service changes. |

## Repeated audit

Independent review and browser testing found and corrected additional issues after the first implementation: server/client clock disagreement, lost-permit recovery after reload, connection-pool waiting, rollback schema-check ordering, redirected readiness and a non-200 frontend. Tests must pass on the final combined source, followed by hosted CI and actual public verification. Release evidence is saved separately under artifacts so credentials and private runtime configuration cannot enter Git.

The combined local verification passed 155 integration tests, including all six actual production transport checks with no skips, and 25 authentication tests. The frontend build passed two storage and five permit regressions, TypeScript and all 889 locale keys in Russian, English and Chinese. A final independent cross-review found the PAT/OAuth quota interaction and prompted a separate PostgreSQL regression before publication. Hosted CI repeats the complete suite for the exact published revision.

## Operational baseline and remaining work

The shared host snapshot had 3911 MiB RAM with 1682 MiB available and about 11 GiB disk free. Read-only sequential public sampling measured ready/catalog responses in tens of milliseconds. This is a small latency snapshot, not a measured advertising capacity or stress test. `scripts/check-public.py` performs bounded unauthenticated GET checks, does not follow redirects or disclose response bodies, and exits nonzero on a failed check. It creates no scheduler and sends no alerts.

Still required: scoped GitHub repository API credentials, password-recovery provider/policy, external alert delivery, recurring off-host backup destination/retention and a second secure recovery copy of the encryption key, useful public work, fuller accessibility/load assessment and deeper frontend splitting. PR draft text remains in memory and clears on a full reload. Real HIGH/CRITICAL dispatch remains disabled pending attestation. Existing private task drafts are not marked as merged contributions by this maintenance release.
