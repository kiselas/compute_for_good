# Interface languages

ComputeForGood supports English (`en`), Russian (`ru`) and Simplified Chinese (`zh-CN`). The language selector is available in the public header and participant workspace, including mobile.

Selection order: saved `cfg-language` preference, first supported browser language, then English. Chinese browser variants currently select Simplified Chinese. Switching changes the interface without navigation, logout or remounting forms. The preference is local to the browser and synchronizes across tabs; disabled browser storage does not prevent switching in the current tab.

## Implementation

- `frontend/src/locales/en.json`, `ru.json`, `zh-CN.json` contain the UI dictionaries. English source phrases are stable lookup keys; translating a page requires no DOM mutation or external translation service.
- `frontend/src/i18n.ts` provides `t`, `useLocale`, date/number formatting and document language/metadata updates. Named placeholders preserve values while translators control word order. Values are rendered as React text, not HTML.
- `LanguageSwitcher.tsx` provides accessible native labels in each language: English, Русский, 简体中文.
- API requests send `Accept-Language`. Current REST/MCP protocol enums, IDs and business data remain stable; the browser translates known server errors and event labels for display.

User-authored project descriptions, task contracts, review findings, usernames, repository names and URLs retain their original language. MCP commands, configuration, token values, scopes, SHA and verifier commands are never translated. Automatic repository-content translation is outside this feature.

## Adding or editing text

Wrap UI prose with `t("English source")`; add the same key to all three catalogs. For variable sentences, use `t("Contribution to {task}", { task: title })`. Dates and numbers use the locale-aware formatters. Do not translate API paths, form field names, enum values or client configuration. Feedback stored in component state should retain its source message and be translated on rendering.

Run `npm run check:i18n` from `frontend/`. It validates catalog parity, named placeholders, literal key coverage, untranslated JSX, protocol-value guards, fallback, persistence, cross-tab changes, document language and date/number formatting. The production build runs this check before TypeScript/Vite. Browser verification additionally checks all three languages, mobile wrapping and preservation of a form draft while switching.

The SPA uses one set of route URLs. Per-language search landing URLs, prerendering and a translated user-content model can be added later if needed. Existing backend verification evidence remains recorded separately from interface-language verification.
